## 一、用户判断 (待验证的原话)
> 把信息的压力全部给到识别层; 识别出来之后只是「字」;
> 所以识别意图什么的几乎不需要什么信息;
> 然后极大增加速度和推力。

拆成两个可测的命题:
- **P1 速度**: 识别层一次性付清后, 下游推理应该极快。
- **P2 信息**: 识别→离散符号这一步, "几乎没有消失什么"。

## 二、实测三连 (真实 48 词 × 896 维 0.5B 嵌入)

### 实验A `appearance.py` — 意思比外观「浓缩」
| 任务 | 最小维度 k (达 85%) |
|---|---|
| 区分「意思」(8类) | **k=8** |
| 区分「外观」(8类) | 做不到 (信息散在几百维) |
| 嵌入能量占比 | 意义 **27.8%** / 外观 **7.3%** / 其他 65% |

→ 语义结构在嵌入里高度集中 → 「识别完字之后意图不需要多少信息」**方向正确**。

### 实验B `topreason.py` — 速度 ✅ / 长链 ❌
| 指标 | 结果 |
|---|---|
| 速度 (符号查表 vs 896×896 连续) | **×1733** (实测) / ×802816 (FLOP 比) |
| 单步信息损失 | 16 符号保住 88% 类别保真, 分类 89% vs 97% |
| **长链推理保真度** | L=1: 0.83 → L=20: 0.085 → **L=200: 0.0007 (崩)** |

→ 速度命题成立; 「几乎没有消失」**只在单步成立, 长链必崩**。

### 实验C `topreason2.py` — 换码本/换变换都救不了
| 配置 | L=200 保真度 |
|---|---|
| 正交保距 + 随机码本 | 0.006 ❌ |
| 正交保距 + 自洽码本(64) | 0.007 ❌ |
| 收缩非线性 + 自洽码本 | 0.017 ❌ |

→ **问题不在码本质量, 在任务本身**: 只要下游仍是「向量几何」, 离散化误差必然被放大。

### 实验D `topreason3.py` — 换成形式化封闭任务, 反而精确
| 实现 | 首次出错步 | L=2000 正确率 | 耗时 |
|---|---|---|---|
| **整数符号 (精确)** | **永不出错** | **1.0000** | 0.0006s |
| float64 连续 | 第 2 步 | 0.0010 | 0.0005s |
| float32 连续 | 第 1 步 | 0.0005 | 0.0042s |

→ 浮点从第 2 步就全错; 整数环对这个运算是**封闭**的, 所以 2000 步 100% 精确且更快。

## 三、★ 三个结论

```
① 速度: 用户判断【无条件成立】
   识别层一次性付清 → 下游 O(1) 查表 → 千倍加速
   "推力"来自: 高维几何运算被换成离散查表

② 信息: 「几乎没有消失」是有条件的
   判据不是"丢了多少信息", 而是"下游任务需要的信息丢没丢"
   · 几何/连续任务  → 量化=丢连续坐标 → 长链必崩 (0.0007)
   · 形式化封闭任务 → 符号=精确代数元 → 长链无损 (1.0000)

③ ★ 分水岭: 下游是否【形式化封闭】
   封闭 (整数环/模算术/置换群/类型系统) → 符号精确 + 极快  ✅
   不封闭 (语义相似/图像/风格)          → 符号只是压缩, 会崩 ⚠️
```

**这就是 Lean / 编译器 / 形式系统能做到零精度损失而神经网络不能的根本原因。**

---

## 四、对项目的落地 (三条)

```
① 识别层设计目标不是"最小", 是"认出符号身份"
   识别层有损没关系 (实测相对误差 0.35), 只要符号身份对
   → 认出身份 → 下游 100% 精确; 认错 → L1 验证器立刻发现

② 下游必须外挂【封闭代数】, 不能继续用向量运算
   语言/图像 → 先用识别层压成符号 → 交给整数环/集合/图 等封闭结构

③ 「无解/边界」仍由验证器给出 (接 V167)
   生成器 (符号层) 只能给候选; 验证器 (L1) 判真假
   → 与 boundary.py 的「否定即边界」同源
```

## 六、★ 一句话
> **把信息压力给识别层, 速度上必然暴涨 (千倍); 但要"什么都不丢", 下游必须换成封闭的符号代数 —— 否则识别层省下的时间, 会被下游放大错误的时间吃掉。**
> **快是对的, 准是有条件的。条件就是: 符号必须活在一个封闭的世界里。**
