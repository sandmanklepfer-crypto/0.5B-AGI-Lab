## 一、被检验的假设

**用户机制（= pipeline.py 的小步版）：**
```
走一小步(1%) → 验证语义没崩 → 固化 → 再走一小步 → 循环 N 轮 → 涌现/累积变强
```

**V170 只验证了"单步"可行（预算 1~3%）。V171 检验"累积"是否成立。**

## 三、三个副产品发现

| # | 发现 | 数据 |
|---|---|---|
| ① | **完全可预测** | 想达到某强度不用试，直接算：N 轮 = N×ALPHA |
| ② | **不会失控** | 线性累积，非指数爆炸（比预想安全） |
| ③ | **存在饱和点** | 每轮增量 0.70%→0.57% 递减，外推约 70 轮 / 总偏移 ~25% |

### ★ 最惊人的发现：谱集中度几乎不动

```
16 轮：谱集中度 47.7% → 51.7%  (只 +4%)
但：   困惑度已崩 3.11 倍
```

**权重对谱分布极度敏感，但谱分布的可调空间又极小 —— 一个"脆弱的窄窗口"。**

---

## 四、★ 根因：桥基是固定的，所以只有加性

```
固定桥 B0 (第 0 轮算的 250 维) → 之后 16 轮全用同一座桥
                              → 加性操作
                              → 线性累积
                              → 无涌现
```

**这与用户 `pipeline.py` 的真实机制有本质差别：**

| | pipeline.py | V171 实现 |
|---|---|---|
| 做法 | 跳跃 → 形式化 → **固化** → 重新跳跃 | 走一步 → 走一步 → 走一步 |
| 桥/规则 | **每轮重建** | ❌ 固定 |
| 预期 | 正反馈、加速 | 线性 |

**V171 证伪的是"固定桥的累积"，不是用户的流水线机制本身。**

### 正确的下一步 = 动态桥（D 实验）

```
第1轮: 建桥 B1 → 重流 → 固化
第2轮: 用【新权重】重建桥 B2 → 重流 → 固化   ← 关键差别
第3轮: 重建 B3 → ...
```

**代价**：每轮重新 SVD（约 19 秒/轮）。

## 五、工程细节

| 项 | 值 |
|---|---|
| 一次 SVD 缓存 | 168 组，18.6 秒 |
| 反复重流（改 S） | 秒级（不需重新分解） |
| `torch.set_num_threads` | **8**（112 会慢 100 倍） |
| 停止条件 | ratio > 3.0 |

### 关键优化（可复用）
**因为只动 S 不动 U/Vᵀ，反复重流不需要重新 SVD：**
```python
# 一次分解
U, S, Vh = svd(W)
# 之后每轮只改 S
S = S * (1 + alpha*tail/head); S *= S.norm()/S.norm()   # 能量守恒
W = (U * S) @ Vh
```

## 六、结论

| 命题 | 判定 |
|---|---|
| 小步走 N 轮 → 累积变强 | ❌ **只是等价于一次迈大步** |
| 流水线反复转 → 涌现 | ❌ **无涌现，纯线性叠加** |
| 安全窗口 | ⚠️ **仅 3 轮（总偏移 2.1%）** |
| 累积会失控吗 | ✅ **不会，线性且饱和** |
| 桥流机制本身成立吗 | ✅ **单步成立（V170）** |

> **"固定桥 + 反复走" 被证伪。**
> **要验证用户的流水线，必须"每轮重建桥"（D 实验）。**
