常驻内核之上
脉冲一切应用

PulseOS 把「进程常驻」替换为「状态驻留」。 应用在两次调用之间不存在，只在需要的那几毫秒里存在。 空闲时它只占磁盘上一个 118 字节的状态箱——不占 CPU，不占内存。

01为什么需要它

四个被普遍接受的浪费。

常驻即浪费

一个典型站点 99% 的时间在等请求。但为了这个「等」，你得维持一台虚拟机、一个操作系统、一个 Web 服务器、若干运行时进程。

你付 100% 的账单，买到 1% 的计算。

冷启动地狱

Serverless 解决了空闲浪费，却引入数百毫秒到数十秒的冷启动。原因很简单——状态太大，镜像需要被反复加载、解压、初始化。

状态越大，恢复越慢。这是根本矛盾。

为定时任务启动服务器

跑一个每天执行一次的脚本，需要一台机器、一个 OS、一个容器运行时、一个调度器。运维复杂度远超任务本身。

为一个 3 秒的任务，养一台 24 小时的机器。

密钥散落在云端

API 密钥通常被注入云端镜像或配置中心。一旦镜像泄漏、日志误打、权限配错，密钥即刻外泄。而密钥一旦离开你的设备，你就再也无法证明它没被复制。

你无法证明一件已经交出去的东西仍然安全。

02核心能力

毫秒级脉冲唤醒

一次完整脉冲包含三个阶段，激活与挂起占了 99% 的时间。

所以：优化业务逻辑没有意义，优化状态大小才是一切。

① activate   从状态箱恢复    1.9 ms
② work       运行业务逻辑    0.004 ms
③ suspend    落盘 + 释放内存 2.7 ms
──────────────────────────────
   p50 4.7 ms  ·  p95 7.1 ms  ·  p99 8.5 ms

状态与数据量脱钩

这是最关键的一项能力。传统做法把全部数据塞进状态，状态随数据线性膨胀。

PulseOS 用日志结构存储——数据进只追加的段文件，索引存在段尾，热状态里只有一个段清单和游标。

它不限制你的数据量，只限制你的「活跃状态」大小。

数据量磁盘状态箱
100 条<1 KB160 B
5 000 条21 KB177 B
200 000 条868 KB196 B
300 000 条1.27 MB197 B
1 000 000 条4.24 MB118 B*

* 压缩后。数据翻一万倍，热状态只翻 1.2 倍。

BYOK 密钥模型

系统本身不持有任何密钥。密钥留在用户自己的设备上，远端节点只发问题、只收答案。

安全性来自架构，不是来自加密——密钥从未离开过那台设备，因此不存在「传输中被截获」这件事。

这同时解决滥用：每个用户用自己的额度，架构上无法借用他人算力。

┌─ 用户设备 ──────────────┐
│  .secrets/*.env         │  ← 密钥只在这
│  vault                  │
│    收请求 → 调API → 回   │
└─────────────────────────┘
           ↕ 信令
┌─ 远端节点 ──────────────┐
│  只发问题，只收答案      │  ← 拿不到密钥
└─────────────────────────┘

算力分层路由

同一份状态箱可在不同层级恢复。调度器按延迟预算自动选层，从便宜到贵。

T0 + T1 覆盖 95% 的使用场景，且零成本。

层来源延迟定位
T0本机<10 ms主力
T1邻居设备0.3~3 s协作
T2公共 CI18~128 s离线批处理
T3付费云主机<1 s高可用兜底

03架构：把「操作系统」拆开

PulseOS 的核心判断是——「完整操作系统」这个词必须被拆成两层来看。

层级运行机制说明
硬件 / 宿主内核常驻由物理机或云平台提供。PulseOS 不改动、不虚拟化、不模拟
init / 系统服务部分常驻依赖宿主进程树，负责基础网络与存储挂载
服务进程脉冲核心创新层。按需唤醒，执行完毕立即释放
用户会话与数据状态箱序列化为游标与索引，随时打包、随时恢复

明确不做的事

不自研内核

内核状态巨大、硬件绑定、无法序列化。这是物理约束，不是工程取舍。

不模拟指令集

模拟器消耗算力而非创造算力。实测 qemu 模拟比原生慢 7.9 倍。

不脉冲化 init

PID 1 被挂起会导致全部子进程变孤儿并被清理。

边界画在这里，是因为越过这条线之后，一切都将失效。

05部署

无外部依赖，Node.js 18+ 即可。不需要 Docker，不需要 Nginx，不需要面板。

  1. 拉取代码

    git clone https://github.com/sandmanklepfer-crypto/0.5B-AGI-Lab.git
cd 0.5B-AGI-Lab/aivault

    核心引擎在 aivault/，官网与文档在 pulseos/ 与 docs/。

  2. 验证环境

    node --version        # 需要 18 或更高
node agent/brain.js --help

  3. 放置密钥（可选，仅需 AI 能力时才做）

    mkdir -p .secrets
cat > .secrets/deepseek.env <<'EOF'
DS_KEY=你的key
EOF

    .secrets/ 已在 .gitignore 中。密钥只留在这台设备的磁盘上，不会进入命令行参数，因此 ps aux 也看不到。

  4. 启动 vault（密钥持有端）

    export VAULT_CHAN=你的随机频道名
node vault.js

    看到 [vault] 就绪，监听 zhz/vault/<频道>/ask 即成功。
    provider 会自动从 .secrets/*.env 发现，无需配置。

  5. 常驻运行

    setsid nohup env VAULT_CHAN=你的频道名 node vault.js \
  > /tmp/vault.log 2>&1 < /dev/null &

    ⚠️ Android 沙箱会随宿主 App 退出而清理进程。要真正 7×24，请部署到 Termux 或一台常开的 Linux 主机。

  6. 从远端验证

    VAULT_CHAN=你的频道名 node agent/brain.js --status
    ✓ vault 在线（心跳 16 秒前）
  provider : deepseek, hunyuan3d
  本小时已用: 0 次
  限额      : {"maxTokens":2000,"maxCallsPerHour":60,"maxInputChars":8000}

  7. 发起调用

    VAULT_CHAN=你的频道名 node agent/brain.js "用一句话解释什么是状态机"

06命令参考

运行时可编程接口

const { Proc2 } = require('./proc2');

const proc = new Proc2({
  name: 'notes',
  handlers: {
    add:  (store, _, text) => ({ state: null, result: store.append({ t: text }) }),
    list: (store, _, n)    => ({ state: null, result: store.tail(n) }),
    at:   (store, _, i)    => ({ state: null, result: store.get(i) }),
  },
}, '/var/pulse/notes');

let box = null;                      // 状态箱：初始为空
let r = proc.pulse(box, 'add', '第一条');
box = r.bytes;                       // 118 字节，随便存哪里

r = proc.pulse(box, 'list', 10);     // 从 118 字节恢复
// r.totalMs ≈ 7 ms

box 就是全部需要持久化的东西。它小到可以放进一个 MQTT 消息、一个 Git 提交、一行数据库字段。

07适用与不适用

✅ 适合

  • AI Agent 执行环境
  • 微服务网关与信令路由
  • 物联网边缘调度
  • 定时任务与自动化脚本
  • 轻量游戏服务器信令层
  • 多租户 BYOK 服务

❌ 不适合

  • 重型桌面 GUI 应用
  • TB 级本地磁盘 I/O 数据库
  • 要求 100% SLA 的交易系统
  • 实时音视频流
  • 秒级以内必须响应的控制回路

PulseOS 不是万能引擎。它在「稀疏调用 + 小状态」这个象限里是极优解，在其他象限里不成立。

08常见问题

它是操作系统吗？

不是。它是运行在宿主操作系统之上的一层运行时。内核由宿主机提供，PulseOS 只负责脉冲其上的服务、会话与数据。
之所以叫「OS」，是因为它管理的是「什么在运行、状态存在哪、何时唤醒」——这本来属于操作系统的工作。

和 Lambda / Firecracker 什么关系？

同一技术谱系的不同切口。它们是通用的 Serverless 平台；PulseOS 是面向「状态极简」场景的极窄优化——放弃通用性，换取状态箱的极致压缩。

为什么要 BYOK？把密钥放服务端不是更方便？

方便，但不安全。密钥一旦离开你的设备，你就无法证明它没有被复制、没有被日志记录、没有在某个备份里存活十年。
BYOK 的代价是每个用户要自己管密钥；收益是你不需要信任任何平台。

7.1 ms 是真的吗？怎么测的？

真。ARM64 / Android 15 沙箱 / Node 18，4 个服务、358 字节状态、1000 次连续激活的统计结果。
node demo.js 可复现。注意它是「小状态」下的数字，状态到 300 KB 就会变成 31 ms。

能用 GitHub Actions 跑吗？

能，但只能做 T2 层——离线批处理。它的定位是「提交任务 → 等 1~2 分钟 → 拿结果」，不是交互式服务。
请遵守平台条款：设计用途是构建与测试，单次运行有时长上限，不应用于长时间占位、代理转发或与项目无关的活动。

现在能用于生产吗？

核心引擎已验证，但还不是生产级存储。当前缺失：删除语义、段合并、并发控制、CRC 校验。
在这四项完成前，不要用它承载不可恢复的数据。

为什么不做软件模拟指令集？

因为模拟器消耗算力而非创造算力。实测 qemu 模拟 x86 比原生 ARM 慢 7.9 倍——你想「多出算力」，结果反而多花 8 倍。
这是热力学问题，不是工程问题。
